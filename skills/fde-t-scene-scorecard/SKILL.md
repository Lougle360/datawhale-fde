# T-04 场景评分卡

多候选场景排序，选出第一单。七维度全过才是第一单；不过的按缺项回补。

**挂载**：2.3、6.4。全自动判断：对每个场景打分并给理由。

## 何时用

- 候选场景 ≥ 2，要选第一单。
- 二期新需求要重排。
- 用户问「这个能不能做 AI」。

## 需要的输入

- 候选场景清单（一句话问题 + 发生在哪一步）
- 各场景价值链（来自 T-03 / 2.2），没有则先转 `fde-t-why-chain`
- 可选：`01-diagnose/data-ladder.md`、干系人意愿

## 步骤

对每个场景按顺序问七问，只能答「过 / 不过 + 证据」：

1. **高频、重复成本高？** 不过 → 降级为普通数字化或放弃。
2. **可算钱？** 能挂到收入 / 成本 / 风险 / 关键人时间。不过 → 放弃或先做基线采样。
3. **工作流可定义？** 不过 → 先做 3.3 知识萃取再回来。
4. **数据可得、可写回？** 不过 → 先做 3.4；信息化未完成则先补记录。
5. **当前 AI 够用，而不是脚本 / 算法更合适？** 传统更合适 → 标「不上 AI」，仍可做。粗判可调 `fde-t-human-ai-split`。
6. **业务有意愿有预算，一号位愿用？** 不过 → 先做加工具型破冰。
7. **正反馈快、涉及人少、用户投入小？** 慢 → 列入二期。

七项全过 → **第一单**。多项全过时，选正反馈最快、涉及人最少的。

全部不满足 → 先做加工具型小点破冰（见路由 skill 三档规模），不硬上大框架。

## 输出

按 [templates/scorecard.md](templates/scorecard.md) 写到：

`projects/<客户>/02-define/scorecard.md`

（6.4 调用则写到 `06-sustain/scorecard.md`。）

## 完成标准

- 每个场景七问都有过 / 不过和一句证据。
- 明确标出第一单，或明确「无第一单，破冰建议」。
- 缺项写清回补去向（3.3 / 3.4 / 破冰 / 二期）。

## 常见误判

- 拿着锤子找钉子，先定技术再找场景（NO.8 反面）。
- 把需求列表直接变成功能列表。
- 为 AI 而 AI（NO.20 金融机构生图：好看不算钱）。
- 七问只过四五项就宣称第一单。
