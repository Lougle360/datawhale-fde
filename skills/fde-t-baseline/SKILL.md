# T-07 效果基线表

上线前记现状，上线后对比。如实区分「已证明 / 尚待验证 / 下降」。基线没记，效果就说不清。

**挂载**：2.4、4.4、6.1。全自动判断：缺数字就标「待采样」，不编造。

## 何时用

- 第一单已定，要定义 ROI 与确认人（2.4）。
- MVP 跑完，要和基线对比并请业务方确认（4.4）。
- 上线后周期监控（6.1）。

## 需要的输入

- 第一单场景与价值链（`02-define/value-chain.md`）
- 现状数据：耗时 / 错误率 / 发现率 / 周期 / 金额 / 使用率，能拿到几项写几项
- 4.4 / 6.1 时还要实验结果或运行数据

禁止：用行业平均值或案例数字冒充本客户基线。案例只作指标选型参考。

## 步骤

1. 选指标。默认六类里只留价值链能支撑的：耗时、错误率、发现率、周期、金额、使用率。
2. 问三句（2.4 必问）：
   - 解决后一年少多少损失 / 多多少收入？
   - 这个数怎么算、数据从哪来？
   - 项目结束时谁来说「对，这笔钱是因此省的」？
3. 上线前写入「现状值」。没有数字 → 安排一轮人工采样，不进入「已证明」。
4. 约定目标值与确认人。
5. 上线后周期记录，每项标注：已证明 / 尚待验证 / 下降。
6. 对外表述只引用已证明项，与数据一致（NO.20 上线短不夸大；NO.24 脱敏但量级真实）。

## 输出

按 [templates/baseline.md](templates/baseline.md) 写到：

`projects/<客户>/02-define/baseline.md`

4.4 对比结果追加到同文件「对比」节，或写 `04-mvp/baseline-compare.md`。
6.1 周期记录写 `06-sustain/effect-report.md`。

## 完成标准

- 至少一项现状值有数字或明确「待采样 + 采样计划」。
- 确认人有姓名 / 角色。
- 已证明与尚待验证分开写，没有用案例数字冒充本项目效果。

## 常见误判

- 基线没记就宣布省了多少钱。
- FDE 自己宣布有效，业务方没点头（4.4 退出标准是业务人员亲口说）。
- 交付后权限被移除，效果无法追踪（NO.22）。
- 把过程指标（识别率 95%）当成业务结果（省了多少钱）。
