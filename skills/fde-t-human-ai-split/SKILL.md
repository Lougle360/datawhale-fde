# T-05 人机分工决策树

对每个业务环节判定归属：RPA / 脚本、专业工具 / 算法、固化规则、LLM 工作流、单核心 Agent、人负责、AI 初筛 + 人确认。

**挂载**：3.2、4.5、6.4。全自动判断：直接给判定和理由，不等人确认即可产出表。

## 何时用

- 阶段 3 环节表已就位，要标每个环节谁做。
- MVP 失败、怀疑分工错了，要重判。
- 二期新场景粗判要不要上 AI。

## 需要的输入

至少具备其一：

- `projects/<客户>/03-design/step-table.md`（环节表）
- 或用户当场列出的环节清单（谁做 / 输入 / 输出 / 判断点）
- 可选：`01-diagnose/sop-draft.md`、套用的 M-xx 模板

缺环节表时先停，让用户补，或转 `fde-03-design` 做 3.1。

## 步骤

对**每一个环节**独立走树，不要整条链一次判完。

1. 规则完全确定？
   - 是，且跨系统搬运 / 填写 → **RPA / 脚本 / 定时任务**
   - 是，且精确计算 / 寻优 → **专业工具 / 传统算法 / 确定性代码**
   - 是，其余 → **硬编码规则 / 固化工作流**
2. 规则不确定，需要语义理解 / 非结构化处理？
   - 是，且高频、路径固定 → **LLM 工作流**，再挂 **AI 初筛 + 人确认**
   - 是，路径不固定 → **单核心 Agent 调度工具**，再挂 **AI 初筛 + 人确认**
3. 不需要语义理解？
   - 依赖信任 / 关系 / 审美 / 责任 / 最终决策 → **人负责，AI 只给上下文**
   - 其余 → **AI 初筛 + 人确认**

硬规则：

- 规则确定 → 不用大模型。
- 涉及签字、报价放行、审核尺度、审美、客户关系 → 人。
- 不要用多智能体互聊扛业务（NO.4 上下文丢失）；单核心 Agent + 工具。
- 不要端到端让模型直接出报价 / 图纸（NO.17 失败）；改为结构化 + 规则匹配 + 人校准。

## 输出

按 [templates/split-table.md](templates/split-table.md) 写到：

`projects/<客户>/03-design/split-table.md`

（若在 4.5 / 6.4 调用，写到当前阶段目录，文件名仍用 `split-table.md`。）

每行必填：环节、归属、理由（对应树上哪一问）、兜底人、是否需置信度阈值。

## 完成标准

- 所有环节有且仅有一个归属。
- 涉及信任 / 责任 / 审美 / 最终决策的环节是「人负责」或「AI 初筛 + 人确认」，不能是纯自动。
- 每条理由能指回决策树的具体分支。

## 常见误判

- 把所有事塞给大模型。
- 精确计算（装箱、提成、补货公式）交给 LLM 心算，而不是工具。
- 跳过知识萃取，让模型「自己理解业务」（NO.14）。
- 某环节 AI 不够用、人也不想做 → 不要硬分，回 2.3 重估场景。
