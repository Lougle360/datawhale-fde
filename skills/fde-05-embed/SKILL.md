# 阶段 5 · 嵌入与推广

把验证过的能力放回原有工作流，从关键人到小组到部门，配套组织与激励，陪跑到真正用起来。

**门 5**：员工不需要学一套新系统；AI 成为原流程中的一个节点；上线后有人持续用，且用法被观察和修正。

**人机边界**：5.2 / 5.4 人做、agent 备料；5.1 / 5.3 / 5.5 半自动。

## 何时用

门 4 已过。

## 需要的输入

员工今天在哪工作、1.1 干系人、门 4 确认记录。

## 步骤

### 5.1 嵌入原有入口

按 [references/p-08-entry.md](references/p-08-entry.md)：IM / 专业软件内嵌 / 工作台 / 纸质语音。步骤增加、要重述背景、格式不符交付标准 → 改入口。产出 `05-embed/entry.md`。

### 5.2 关键人 → 小组 → 部门

关键人真实任务试 → 问题收敛 → 小组试运行 1–2 月 → 再部署培训 → 部门。某层问题多就停在该层修。修改走 `fde-t-demo-loop`。

### 5.3 培训与启动会

按 [references/p-09-training.md](references/p-09-training.md)。现场水平与预期不符则升降级（NO.7）。员工须知道能做什么、不能做什么、出错找谁。

### 5.4 组织配套

加载 `fde-t-stakeholder-map` + [references/p-10-kpi.md](references/p-10-kpi.md)。AI 是助手不是替代。一号位不背书 → 降级为加工具型，不推组织变革。只有 IT 牵头要推动改成业务或人事。

### 5.5 陪跑迭代

再跟岗（`fde-t-observe-card`），校准回填（`fde-t-calibration-loop`），回归（`fde-t-eval-set`）。把「味道不对」译成前端 / 流程 / 提示词 / 规则 / 模型。连续无阻断且客户能按 SOP 自己改 → 进 6.1。效果持续不达 → 4.5。

## 门 5 检查

[references/gate-5-checklist.md](references/gate-5-checklist.md)。过门 → STATE 阶段 6。

## 完成标准

不另开必须学的新系统；有人持续用；用法被观察过。

## 常见失败

多一个页面还要复制粘贴（NO.2）；技术跑通员工不用（NO.1、NO.14）；IT 牵头变技术项目（NO.14、NO.20）。
